## 1. 요약

외부에 고정한 RGB 카메라 한 대로 물체에서 잡아도 되는 영역과 피해야 하는 영역을 나누고,
로봇손이 어느 방향에서 다가오는지에 따라 파지 후보와 손 자세를 고르는 시스템을 만들었다.
새로운 분할 네트워크를 제안하는 연구가 아니라, 공개 affordance 데이터 학습부터 반자동
라벨링, 실시간 추론, 후보 선택, 실제 손 구동까지를 하나의 동작하는 시스템으로 잇고 각
단계를 검증하는 응용 연구다.

8월 13일에 공개 데이터 정리로 시작해 8월 25일 현재까지의 상태는 다음과 같다.

- **인식**: 공개 데이터 3종(Aff-Grasp, UMD, IIT-AFF)을 하나의 라벨 체계로 통합해
  train 13,930장 규모의 사전학습 세트를 만들고, 자체 촬영 292장으로 미세조정했다. 공개 test
  1,288장에서 mask mAP50 0.836, 학습에 쓰지 않은 실제 머그(`mug_04`) 51장에서 손잡이
  픽셀 IoU 0.756(RF-DETR 계열 기준)까지 올렸다. 공개 UMD test에서는 mAP50 0.791, 픽셀 IoU 평균 0.760이다.
- **후보 선택**: 마스크에서 후보를 뽑아 신뢰도·거리·접근 방향·폭·기능 영역 안전거리·인간
  파지 사전확률 여섯 항으로 점수를 매기고 `PRECISION/WRAP/POWER`를 결정하는 모듈을
  구현했다. 정지 영상에 모의 손 위치를 넣어 손잡이와 몸통 후보가 서로 바뀌는 것을 확인했고,
  실제 카메라 영상에는 손 추적을 붙여 오버레이를 녹화했다.
- **손 제어**: 네 손가락 액추에이터의 위치 피드백을 정상화하고 전 행정 ADC 범위와 이동
  속도를 실측해 보정값을 확정했다. 폐루프 펌웨어는 벤치·실동작 시험까지 마쳤다 — 도달 오차
  ±17, brake 위치 유지, 스톨 기반 적응형 파지, "엄지 먼저" 구동 순서까지 실측으로 확정했고,
  젯슨에서 시리얼로 실제 머그 파지(세 손가락 78~82% 지점 스톨)에 성공했다. 세 프리셋은
  참여 손가락 최대 굽힘 방식으로 확정했다.
- **자세 결정 근거**: 폭 임계값 방식이 실물에서 무너진 것을 계기로, VISOR 판정 868건을
  마스크와 재연결한 기하 분석에서 구조 기반 규칙(종횡비 2.1 경계, 균형정확도 0.936)을
  도출해 교체했다. 로봇손 오검출 대응으로 robot_hand 클래스 추가 실험(N)을 했으나 검증
  설계와 데이터 협소로 실전에서 실패했고, 원인 분석 후 Copy-Paste 합성 복구(O)와 신규
  촬영 반영(P)을 거쳐 **P를 기본 모델로 채택**했다(4.9~4.10절). 이 과정에서 실시간
  파이프라인의 클래스 번호 기준 버그를 찾아 고쳤고(그간의 라이브 이상 증상 다수의 숨은
  원인), 파지점 좌표를 판정에서 빼고 **부위 수준으로 결정**하는 설계로 전환해(7.4절)
  실물 파지까지 검증했다.

정량 결과 중 가장 중요한 것은 학습에 한 번도 쓰지 않은 네 번째 실물 머그에 대한 평가다.

| 모델 | 자체 학습 데이터 | 손잡이 픽셀 IoU(평균) | 손잡이 완전 누락 | 몸통 픽셀 IoU(평균) |
|---|---|---:|---:|---:|
| H (YOLO11s) | 머그 140장 | 0.4315 | 47장 중 16장 | 0.8610 |
| K (RF-DETR Nano) | 머그 140장 | 0.6662 | 47장 중 10장 | 0.9310 |
| L (YOLO11s) | 머그 + 가위·드라이버 | 0.6247 | 47장 중 8장 | 0.8587 |
| M (RF-DETR Nano) | 머그 + 가위·드라이버 | 0.7557 | 47장 중 5장 | 0.9066 |

몸통은 어떤 모델이든 잘 잡는다. 문제는 손잡이였고, 자체 데이터에 다른 범주(가위·드라이버)를
넣는 것과 모델 계열을 바꾸는 것이 둘 다 손잡이 성능을 올렸다. 완전 누락이 16장에서 5장으로
줄어든 것이 이번 확장에서 얻은 가장 실질적인 개선이다.

아직 하지 못한 것도 분명하다. 실제 파지 성공률 실험(Baseline 대 제안 방식)은 도구까지
준비되어 실행 직전이고, 미학습 인스턴스 평가는 머그 한 종류에만 있다. 이 보고서는 그
경계를 명시하는 데에도 지면을 쓴다.

## 2. 문제 정의와 범위

### 2.1 무엇을 만드는가

목표는 한 문장으로 정리된다. 카메라 영상에서 물체의 `grasp_region`과 `functional_region`을
분할하고, 로봇손의 접근 위치와 방향에 가장 적합한 후보를 선택한 뒤 Brunel Hand를
`PRECISION`, `WRAP`, `POWER` 중 하나의 자세로 구동한다.

대표 시연은 머그컵이다. 손이 손잡이 쪽에서 접근하면 손잡이를 골라 감아쥐고, 몸통 쪽에서
접근하면 몸통을 움켜쥔다. 가위처럼 날이 있는 물체에서는 날을 피해 손잡이 쪽으로 유도한다.
같은 물체라도 손이 어디 있느냐에 따라 답이 달라진다는 점이 이 시스템의 핵심이다.

### 2.2 범위 밖

로봇팔로 손을 자동으로 옮기는 부분과 RGB-D 기반 6-DoF 파지 자세 생성은 처음부터 범위에서
제외했다. 사용자가 손을 물체 근처까지 가져가면 시스템이 어디를 어떻게 잡을지 결정하는
반자율 방식이다. 접근 방향도 영상 평면에서 측정한 2차원 상대 위치와 방향이다.

주장할 수 있는 범위는 학습에 쓰지 않은 실물 인스턴스와 제한된 미학습 범주까지다. 임의의
물체를 다루는 open-world 시스템이라고 말하지 않는다.

`functional_region`은 물리적으로 못 잡는 영역이라는 뜻이 아니다. 이번 작업에서 기능 보존과
안전을 위해 피해야 하는 영역이라는 뜻으로 쓴다.

### 2.3 파이프라인

```text
외부 고정 RGB 카메라
   ↓
YOLO11s-seg / RF-DETR-Seg  →  handle / body / functional 마스크
   ↓                                   ↓
후보 추출(연결 성분 분리,          기능 영역은 후보가 아니라
distance transform 안전 내부점)     회피 대상으로 별도 보관
   ↓
손 추적(위치·접근 방향) + 후보 점수화
   ↓
GRASP / ALIGN / NO_TARGET  +  PRECISION / WRAP / POWER
   ↓
USB Serial → Arduino Nano 33 IoT → DRV8833 ×2 → PQ12 ×4 → Brunel Hand
```

## 3. 데이터

### 3.1 라벨 정책

모든 원본 라벨을 통합 라벨로 바꾸는 규칙을 먼저 고정하고 시작했다. 이 규칙은 프로젝트 내내
바꾸지 않았다.

| 원본 | 통합 라벨 |
|---|---|
| Aff-Grasp `graspable` / UMD `grasp`, `wrap-grasp` / IIT-AFF `grasp`, `w-grasp` | `grasp_region` |
| Aff-Grasp `functional` / UMD `cut, scoop, pound, support` / IIT-AFF `cut, display, engine, hit, pound, support` | `functional_region` |
| UMD·IIT-AFF `contain` | `ignore` (255) |
| 의미가 겹치거나 알 수 없는 픽셀 | `ignore` (255) |

`contain`을 `functional_region`으로 바꾸지 않은 이유는 단순하다. 그렇게 하면 컵 몸통 전체가
피해야 할 영역이 되어 몸통을 움켜쥐는 시연 자체가 불가능해진다. 애매한 픽셀을 억지로 한쪽으로
몰지 않고 `ignore`로 남기는 원칙은 나중에 문제를 일으켰고(4.2절), 그 문제를 푸는 과정이
이 프로젝트에서 배운 것 중 하나다.

8월 19일에 클래스 구성을 두 개에서 세 개로 바꿨다. 손잡이형 파지와 몸통형 파지는 손 자세가
다른데 하나의 `grasp_region`으로 묶으면 모델이 그 구분을 알려줄 수 없다. UMD의 `grasp`와
`wrap-grasp`가 이미 그 구분을 담고 있어서 이를 살리는 쪽으로 재매핑했다.

```yaml
0: handle_grasp_region   # UMD grasp, IIT grasp, 자체 손잡이
1: body_grasp_region     # UMD wrap-grasp, IIT w-grasp, 자체 몸통
2: functional_region
ignore_index: 255
```

머그 손잡이와 몸통은 같은 파지 영역이라도 별도 인스턴스로 유지한다. 하나로 합치면 후보가
하나가 되어 접근 방향에 따라 고르는 일이 성립하지 않는다.

### 3.2 공개 데이터

| 데이터셋 | 물체 종류 | 규모 | 원본 affordance 라벨 |
|---|---|---|---|
| Aff-Grasp | 칼, 숟가락, 뒤집개, 팬, 포크, 드라이버, 컵, 가위, 국자, 망치, 모종삽, 삽 12종 | 학습용 331쌍, 평가용(AED) 721쌍 | `graspable`, `functional` (2종) |
| UMD Part Affordance | 머그 20, 칼 12, 숟가락 10, 그릇 10, 뒤집개 8, 가위 8, 컵 6, 모종삽 5, 국자 5, 나무망치 4, 망치 4, 톱 3, 고기망치 2, 삽 2, 전지가위 2, 스쿱 2, 냄비 2 = 17종 105개 | 수동 GT 9,632장 | `grasp`, `wrap-grasp`, `contain`, `cut`, `scoop`, `pound`, `support` (7종) |
| IIT-AFF | 그릇, 모니터, 팬, 망치, 칼, 컵, 드릴, 라켓, 뒤집개, 병 10종 | 8,835장 중 8,512장 변환 | 위 7종 + `display`, `engine`, `hit` (9종) |
| 자체 촬영 | 머그 4개, 가위 1, 드라이버 1 | 292장 | 없음. 촬영 시점에 손잡이/몸통/기능부를 직접 부여 |

세 데이터의 역할은 각각 다르다. Aff-Grasp는 `graspable`/`functional` 의미를 배우는 출발점이고
평가용(AED) 721쌍은 학습에 섞지 않고 외부 평가용으로 보존했다. UMD는 도구 형상과 다중 시점을
채우며, 자동 생성 라벨 19,211장은 품질을 믿을 수 없어 제외하고 사람이 만든 것만 썼다. IIT-AFF는
어수선한 실제 장면이라 배경 강건성을 보완한다(2026-08-19 추가 승인).

UMD는 회전판 위에서 찍은 연속 프레임이라 비슷한 장면이 많다. 프레임 단위로 무작위 분할하면
같은 물체가 train과 test에 동시에 들어가 성능이 부풀려진다. 그래서 분할은 실제 물체 ID를
기준으로 하고, 누수 검사를 자동으로 돌린다. IIT-AFF는 장면 단위 데이터라 물체 ID가 없어서
전량 train 전용으로 넣었다. 덕분에 IIT-AFF 추가 전후의 validation·test가 완전히 같아
효과를 공정하게 비교할 수 있었다.

공개 YOLO 변환본은 네 번 갱신했다.

| 버전 | 구성 | train / val / test | 인스턴스 (handle / body / functional) |
|---|---|---|---|
| 2클래스 엄격 | Aff-Grasp + UMD | 2,134 / 470 / 494 | grasp 2,965 / functional 2,973 |
| 2클래스 contain-background | 위 + contain 예외 | 2,836 / 590 / 627 | grasp 4,096 / functional 2,973 |
| 3클래스 v1 | 위를 3클래스로 재매핑 | 5,003 / 1,179 / 1,255 | 6,017 / 1,806 / 5,514 |
| 3클래스 v2 | + IIT-AFF | 12,784 / 1,179 / 1,255 | 14,708 / 3,074 / 13,748 |
| 3클래스 v3 | + 고리형 절개선 | 13,930 / 1,220 / 1,288 | 15,973 / 4,521 / 14,561 |

### 3.3 자체 데이터

공개 데이터만으로 학습한 모델을 실제 광각 USB 카메라에 붙였더니 책상과 벽을 큰 마스크로
잡았다. 신뢰도 임계값을 올려도 충분히 사라지지 않았다. 공개 데이터의 시점·왜곡 분포가 실제
카메라와 너무 달랐기 때문이다. 그래서 실제로 쓸 카메라로 직접 찍기로 했다.

| 대상 | 장수 | 분할 | 촬영일 |
|---|---:|---|---|
| mug_01, mug_02 | 90 | train | 2026-08-14 |
| mug_03 (보온 머그) | 50 | validation | 2026-08-14 |
| 배경만 있는 사진 | 20 | train | 2026-08-14 |
| mug_04 | 51 | **test** | 2026-08-21 |
| scissors_01 | 42 | train | 2026-08-21 |
| screwdriver_01 | 39 | train | 2026-08-21 |
| 합계 | 292 | train 191 / val 50 / test 51 | |

흰 촬영 부스와 사무실 책상 두 배경에서 찍었다. 배경만 있는 20장은 물체가 없는 negative
샘플로, 큰 배경 오검출을 줄이려고 일부러 넣었다.

`mug_04`는 처음부터 미학습 인스턴스 test용으로 예약해 두었고, 촬영 전에는 자체 test 수치를
만들지 않는다는 원칙을 지켰다. 8월 21일에 촬영하면서 가위와 드라이버를 함께 찍었는데, 이 둘은
실물이 한 개씩뿐이라 학습에만 쓴다. 그래서 가위·드라이버 범주로는 미학습 인스턴스 평가를 할 수
없다는 제약이 남는다.

부위 정책은 촬영 시점에 확정했다. 가위는 손잡이 고리 두 개를 각각 별도 `handle_grasp_region`
인스턴스로, 날을 `functional_region`으로 둔다. 드라이버는 손잡이가 `handle_grasp_region`,
축과 팁이 `functional_region`이다. 이 두 물체 덕분에 자체 데이터에 처음으로
`functional_region` positive가 81개 생겼다. 그전까지 자체 데이터에는 파지 영역만 있어서
기능 영역 성능을 자체 데이터로는 검증할 수 없었다.

### 3.4 반자동 라벨링과 사람 검수

Grounding DINO로 부품 텍스트 프롬프트(`mug handle`, `mug body` 등)에 대한 박스를 얻고
SAM2로 마스크를 만든 뒤, 품질 경고와 오버레이를 붙여 사람이 고치는 방식으로 라벨을 만들었다.
Foundation model을 정답 생성기로 쓰지 않고 초안 생성기로만 쓴다는 원칙을 지켰다.

실제로 자동 후보에서 자주 나온 오류는 손잡이 완전 누락, 손잡이 영역이 지나치게 작음, 몸통 일부를
손잡이로 표시, 손잡이 마스크가 몸통까지 번짐, 손잡이가 보이지 않는 각도에서 억지 마스크 생성이었다.
그래서 자동 승인 없이 전량을 사람이 확인했다. OpenCV 기반 수정 도구를 만들어 브러시와 다각형으로
직접 고치고, 승인 단계에서 64픽셀 미만 고립 조각만 정리했다(손잡이 558픽셀, 몸통 346픽셀).
원본 이미지와 검수 workspace는 덮어쓰지 않고 별도 승인본으로 승격했다.

### 3.5 YOLO 폴리곤의 표현 한계와 절개선

Ultralytics의 폴리곤 형식은 구멍이 있는 마스크를 표현하지 못한다. 컵·그릇·팬처럼 안쪽
`contain` 구멍을 두른 고리형 몸통은 단일 폴리곤이 되지 않아 변환에서 제외됐다. 공개 v2에서
`component_not_single_hole_free_polygon` 사유로 빠진 컴포넌트가 3,525개였고 대부분 body
클래스였다.

구멍을 채워버리면 `contain`을 몸통으로 학습하게 되어 정책 위반이다. 그래서 바깥 윤곽과 구멍
윤곽을 폭 0의 절개선으로 이어 하나의 폴리곤으로 만들되, 채웠을 때 구멍 안쪽은 배경으로 남게 했다.
재구성 IoU가 0.85 미만이면 안전하게 제외한다. 기존 데이터셋의 재현성을 깨지 않도록 기본값은
꺼둔 채 v3부터 적용했다.

적용 결과 공개 v3에서 절개선이 3,525개 컴포넌트에 적용됐고 IoU 미달로 제외된 것은 없었다.
body 인스턴스가 3,074개에서 4,521개로 늘었다. 자체 데이터에서도 앞쪽 손잡이가 몸통을 가려
제외됐던 `mug_02`의 몸통 하나가 복원됐다.

### 4.2 공개 사전학습과 contain 오검출

첫 공개 사전학습 모델(YOLO11n-seg, 80 epoch)의 고정 test 494장 성적은 mask mAP50 0.7600,
mAP50-95 0.4968이었다. 숫자만 보면 첫 모델로 무난했다.

그런데 컵·머그·냄비만 따로 골라 117장을 감사했더니 전 장면에서 `contain=ignore` 영역을
`functional_region`으로 예측했다. 덮임 비율은 물체별 평균 96.6~99.0%였고, 정작 있어야 할
`grasp_region`은 117장 모두에서 놓쳤다. 일반 mAP는 이 문제를 전혀 보여주지 않았다.

원인은 라벨이 아니라 변환에 있었다. 통합 PNG에는 `contain`이 `ignore`로 올바르게 저장돼
있었지만, YOLO 폴리곤이 `ignore`를 표현하지 못해 해당 샘플을 통째로 제외했다. 모델은 컵
주변의 올바른 파지 형상을 볼 기회가 없었다.

통합 라벨 정책은 그대로 두고 YOLO 변환본에서만 `contain` 폴리곤을 기록하지 않아 암묵적
배경이 되게 하는 예외를 만들었다. 사유가 정확히 `umd_contain_policy`인 샘플에만 적용하고
다른 `ignore` 사유는 계속 제외했다. 학습 데이터는 2,134장에서 2,836장으로 늘었다.

| | 기존 엄격 모델 | contain-background 모델 |
|---|---:|---:|
| 고정 test 494장 mask mAP50 | 0.7600 | 0.7402 |
| 확장 test 627장 mask mAP50 | - | 0.7599 |
| 정책 감사 117장 위반 | 117장 | 0장 |

일반 test 수치는 조금 내려갔지만 컵 몸통을 못 잡게 만드는 오류가 사라졌으므로 이 체크포인트를
이후 미세조정의 출발점으로 삼았다. 이 예외는 라벨 정책 변경이 아니라 학습 형식의 한계를
보완한 별도 변환이라는 점을 문서에 명시해 두었다.

### 4.3 미세조정에서의 망각과 replay

자체 머그 데이터로 미세조정한 실험 A와 D는 `mug_03` validation에서 좋아 보였다.

| mug_03 validation (mask) | A (COCO→자체) | D (공개→자체) |
|---|---:|---:|
| mAP50 | 0.9154 | 0.8580 |
| mAP50-95 | 0.6992 | 0.4900 |
| Precision / Recall | 0.9426 / 0.8554 | 0.9309 / 0.8424 |

수치만 보면 COCO에서 시작한 A가 낫다. 그런데 D 모델을 실시간 카메라에 붙이자 머그 외의
물체를 거의 검출하지 못했다. 공개 고정 test 627장으로 진단해 보니 mask mAP50이 0.7599에서
0.1189로 떨어졌고, `functional_region`은 정답이 있는 467장 전부에서 아무것도 예측하지 못했다.
자체 데이터에 머그 파지 영역만 있고 기능 영역 positive가 없었기 때문에, 미세조정 과정에서
공개 데이터로 배운 지식이 거의 지워진 것이다.

해결책은 미세조정 데이터에 공개 데이터를 섞는 replay였다. 자체 train을 10회 반복하고 공개
train을 합쳐 자체 비중을 약 28%로 맞췄다(실험 E). 공개 test 627장 mask mAP50이 0.7512로
회복됐고, 기능 영역을 하나도 예측하지 못한 이미지는 467장에서 17장으로 줄었다. 대신 머그
성능은 조금 손해를 봤다(중간발표 기록 기준 mug_03 mAP50 0.858 → 0.784).

이 실험 이후 모든 미세조정은 replay 혼합 방식으로 통일했다. 여기서 얻은 교훈은 공개 사전학습의
가치가 자체 validation 숫자에 나타나지 않는다는 것이다. 가치는 다른 물체와 기능 영역을
계속 인식하는 능력에 있고, 그건 자체 데이터로 측정되지 않는다.

### 4.4 3클래스 전환과 IIT-AFF

3클래스로 바꾼 첫 실험 G의 자체 validation은 mask mAP50 0.6924로, 2클래스 시절보다 낮았다.
손잡이와 몸통을 구분해야 하니 문제가 어려워진 것이 당연하고, 공개 데이터가 3클래스 구분을
충분히 뒷받침하지 못한 탓도 있었다.

IIT-AFF 8,512장을 공개 사전학습에 추가한 실험 H에서 자체 validation이 크게 올랐다.

| mug_03 validation (mask) | G | H | I |
|---|---:|---:|---:|
| 전체 mAP50 | 0.6924 | 0.8966 | 0.9097 |
| 전체 mAP50-95 | 0.3943 | 0.7099 | 0.7124 |
| handle mAP50 | 0.7128 | 0.8182 | 0.8496 |
| body mAP50 | 0.6719 | 0.9749 | 0.9697 |

UMD는 회전판 위 단독 물체라 배경이 단조롭다. IIT-AFF는 실제 어수선한 장면이어서 배경 강건성과
형상 다양성을 보완한다. 공개 validation·test를 IIT 추가 전후로 동일하게 유지했기 때문에 이
차이를 IIT 효과로 볼 수 있다.

### 4.5 절개선 적용(실험 I)

절개선으로 고리형 몸통을 복원한 v3로 다시 사전학습·미세조정한 결과다. 같은 v3 test
1,288장 기준이다.

| v3 test (mask mAP50) | H (절개선 없음) | I (절개선) |
|---|---:|---:|
| 전체 | 0.8277 | 0.8360 |
| handle | 0.7077 | 0.7295 |
| body | 0.9048 | 0.9124 |
| functional | 0.8705 | 0.8660 |

`mug_03` validation도 0.8966에서 0.9097로 올랐다. 기능 영역만 0.005 정도 내려갔는데, 5.6절에
적은 이유로 이 정도 차이는 유의미하다고 말하지 않는다.

한 가지 주의할 점이 있다. v2 test 기준으로 재면 I가 0.782로 H(0.792)보다 낮게 나온다.
I가 복원된 고리형 몸통을 예측하면 v2 정답에는 그 부분이 없어 오검출로 처리되기 때문이다.
정답이 더 완전한 v3 test가 공정한 비교 기준이다.

### 4.6 실패한 실험 J

UMD에서 머그와 컵의 `grasp`/`wrap-grasp` 라벨이 물체마다 일관되지 않는 문제가 있어, 해당
샘플을 정리한 v4 사전학습과 미세조정을 시도했다. 결과는 나빴다.

| | I (v3) | J (v4) |
|---|---:|---:|
| 공개 test 전체 mAP50 | 0.8360 (v3 test) | 0.5641 (v4 test) |
| body mAP50 | 0.9124 | **0.1850** |
| body recall | 0.8640 | 0.0645 |
| 정책 감사 117장 위반 | 0장 | **116장** |

자체 validation만 보면 J는 0.9019로 멀쩡해 보인다. 머그 몸통을 학습 데이터에서 덜어낸 결과
공개 데이터의 몸통 클래스가 붕괴했고, 컵 안쪽을 다시 기능 영역으로 예측하는 정책 위반이
117장 중 116장에서 되살아났다. 자체 validation 하나만 보고 판단했다면 그대로 채택했을
실험이다. 정책 감사를 매 실험에 붙여둔 것이 이 경우에 값을 했다.

J 계열은 폐기하고 I 계열을 유지했다.

### 4.7 모델 계열 비교: RF-DETR

지도교수의 DINO 계열 경험과 연결되는 비교로, RF-DETR-Seg Nano(DINOv2 백본, COCO 사전학습)를
같은 원본 데이터의 COCO 변환본으로 미세조정했다(실험 K). YOLO 변환본을 하드링크로 연결해
COCO 구조로 바꾸는 변환기를 새로 만들었고, 원본은 수정하지 않았다.

이 비교는 단일 변수 통제가 아니다. 초기 가중치(자체 공개 사전학습 대 COCO/DINOv2)와 입력
해상도(640 대 312)가 함께 다르므로 "파이프라인 대 파이프라인" 비교로 읽어야 한다.

계열 비교는 처음에 공개 validation으로 쟀는데, 2026-08-27에 test 분할로 다시 측정했다.
픽셀 IoU 스크립트의 기본 경로가 validation으로 되어 있었고 그대로 써 온 것이라 정당한 이유가
없었다. mAP를 재는 test와 같은 물체에서 비교하는 것이 맞다.

아래는 UMD test 1,255장(물체 16개, 학습 물체 63개와 교집합 없음), 신뢰도 0.25 고정 기준이다.
괄호는 정답이 있는데 아무것도 예측하지 못한 이미지 수다.

| UMD test 1,255장 | handle | body | functional | 평균 |
|---|---:|---:|---:|---:|
| H (IIT-AFF 추가, YOLO11s) | 0.592 (127) | 0.816 (0) | 0.776 (39) | 0.728 |
| I (절개선, YOLO11s 최종) | 0.647 (36) | 0.816 (0) | 0.778 (36) | 0.747 |
| K (RF-DETR Nano) | 0.674 (25) | 0.831 (0) | 0.775 (7) | 0.760 |
| **P (최종 모델, RF-DETR)** | 0.674 (30) | 0.827 (0) | **0.779 (6)** | **0.760** |

분할을 바꾸자 해석이 달라졌다. validation에서는 손잡이 완전 누락이 164장(H)에서 16장(K)으로
줄어 모델 교체가 결정적으로 보였다. test에서는 127장(H)에서 36장(I)으로 줄이는 절개선의
기여가 더 크고, 모델 교체는 36장에서 25~30장으로 완만하다. 기능 영역 완전 누락은 반대로
validation에서 악화로 보였으나(45→62장) test에서는 39장에서 6~7장으로 크게 개선됐다.

validation은 학습 중 성능을 보던 세트라 모델이 그쪽에 유리하게 맞춰졌을 수 있다. 개선 요인을
말할 때는 test 수치를 쓴다. RF-DETR이 손잡이를 놓치는 빈도가 낮다는 경향 자체는 두 분할에서
같고, 신뢰도 임계값을 0.15~0.50으로 바꿔도 유지된다.

두 모델 모두 컨테이너 정책 감사 117장에서 위반 0장을 유지했다. RF-DETR 학습은 early stopping이
일찍 걸려 50 epoch 설정에서 K와 M 모두 12 epoch 안팎에 멈췄다.

### 4.8 자체 데이터 확장(실험 L, M)

`mug_04`를 test로 예약한 채 가위와 드라이버를 학습에 넣은 자체 v3로 두 계열을 각각 다시
미세조정했다. YOLO 계열이 L, RF-DETR 계열이 M이다. 결과는 1절 요약 표와 5.3절에 있다.

### 4.9 robot_hand 클래스 추가: 실패한 실험 N과 복구 실험 O

로봇손이 파지 후보나 기능부로 오검출되는 문제의 근본 해결로, 분할 모델에 네 번째 클래스
`robot_hand`를 추가했다(기존 1~3 클래스 정의와 라벨은 불변, 사용자 승인). 데이터는 젯슨
실환경에서 찍은 손 영상 3개에서 프레임 198장을 뽑아 Grounding DINO("a black robotic hand")와
SAM2로 손 마스크 후보를 만들고 사람이 검수했다(승인 155, 거부 43). 머그가 함께 나오는
프레임 61장에는 모델 M의 예측을 머그 의사라벨로 병합하되, functional 의사라벨 9건은 전부
손·장비 오검출로 확인되어 제외했다.

실험 N(v4)의 지표는 좋았다. robot_hand AP 0.957에 재현율 1.0, 픽셀 IoU 평균 0.92였고 기존
3클래스도 공개 val에서 M과 동급이었다. 그러나 실전에서는 손이 화면에 들어오는 순간 학습에
동반됐던 파란 머그를 제외한 물체 인식이 무너졌고, 파지 중의 닫힌 손은 검출조차 되지 않았다.
바로 롤백하고 원인을 분석했다.

- **검증 설계 실수**: valid에 손-물체 상호작용 장면이 한 장도 없어, 지표가 배포 상황을
  전혀 대변하지 못했다. 좋은 숫자는 진짜였지만 배포와 무관한 진짜였다.
- **데이터 협소**: 손 데이터가 단일 세션·단일 배경·펼친 손·물체는 파란 머그 하나뿐이라,
  모델이 배경·물체와의 허위 상관까지 학습했다.
- **의사라벨 거짓 음성**: 머그 프레임 61장 중 20장에서 M의 손잡이 신뢰도가 문턱(0.5)
  바로 아래라 handle 라벨이 잘렸고, 그 프레임들이 "보이는 손잡이 = 배경"을 가르쳤다.
  자기 예측을 라벨로 쓸 때의 알려진 실패 모드(확증 편향)를 그대로 밟은 것이다.

복구 실험 O(v5)는 촬영 없이 세 가지를 고쳤다. 결함 프레임 20장을 제거하고, 검수 승인된
손 조각을 라벨 완비 물체 이미지에 붙이는 Copy-Paste 합성(Ghiasi et al. 2021)으로 손-물체
겹침 장면 2,320장을 만들었으며(가려진 물체 라벨은 가시 영역만 재계산 — 거짓 음성이 구조적으로
불가능), valid에 합성 상호작용 120장을 포함해 지표가 배포 상황을 측정하게 했다. 합성의
train/valid 손 조각은 영상 단위로 분리해 누수를 막았다.

O의 결과는 절반의 성공이었다. 지표에서는 N의 회귀(custom handle 완전 미검출)를 해소하고
custom body를 전 구간 최고로 올렸지만 public functional 완전 미검출이 46→80으로 늘었고
(합성의 가시 영역 30% 규칙 부작용 추정), 실물에서는 파란 머그·드라이버는 안정된 반면
**실제 파지 접근 자세**(측면·손등·굽힘)의 robot_hand를 놓쳤고 원통 물체와 검정 물체에서
오분류가 이어졌다. 합성이 개방 손바닥 조각만으로 만들어져 시점 다양성이 없었던 것이
핵심 원인이었다.

이 실패들은 보고 가치가 있다. 학습 지표와 배포 성능의 괴리를 실측으로 확인했고, 검증
세트가 배포 시나리오를 포함해야 한다는 요구사항과, 합성 증강은 원천 데이터의 시점
다양성을 넘지 못한다는 한계가 여기서 정량적으로 도출됐다.

### 4.10 실험 P(v6): 신규 촬영 반영과 기본 모델 채택

O의 실물 한계를 겨냥해 접근 자세 손(57초), 실사 상호작용(79초), 원통 물체(148초),
검정 물체(44초) 4종을 추가 촬영했다(총 7.5분, 프레임 820장). M 의사라벨(낮은 문턱
0.25)과 SAM2 손 마스크를 규칙 기반으로 정리한 뒤(배경 장비 functional 989건 자동 제거,
손 겹침 275건 제거, 원통 handle→body 121건 교정) 사람 검수(손 217/339, 물체 427/485
승인)를 거쳐 v6를 구성했다. 합성은 구 세대를 승계하지 않고 전체 손 조각 풀(구 155 +
신 217)로 재생성했으며, valid에는 **손·물체 검수를 모두 통과한 실사 상호작용 56장**을
넣었다 — 한쪽 라벨만 있는 프레임은 보이는 무라벨 물체가 거짓 음성이 되므로 제외했다.

P는 15/50 epoch 조기 종료(최고 EMA mAP 0.6310)했고, 픽셀 IoU 3자 비교에서 사실상 전
항목 최고를 기록하며 O의 public functional 회귀를 해소했다(80→41, M의 46보다도 개선).
접근 자세 손의 미검출은 5장→2장(105장 기준)으로 줄었다. 상세 수치는
`docs/rfdetr_experiment.md`의 실험 P 절에 있다.

**실물 시험에서 파이프라인 버그를 발견했다.** P가 학습 프레임과 같은 조건의 종이컵을
handle 0.9로 표시하는 모순(오프라인 평가는 전부 정상)을 추적한 결과, 실시간 스크립트가
클래스 번호 기준(0시작/1시작)을 매 프레임 검출된 최소 id로 재추정하고 있었다. 우리
모델은 0시작이므로 handle(0)이 없는 프레임마다 모든 클래스가 한 칸씩 밀렸다 —
body→handle, robot_hand→functional. 실험 N 배포 이래 라이브에서 관찰된 "손이
functional로 뜬다", "원통이 handle", "클래스 요동"의 상당 부분이 모델이 아니라 이
시프트였고, 손잡이가 거의 항상 검출되는 머그 장면만 우연히 정상이었다. 수정(확정 증거
잠금) 후 같은 장면에서 증상이 사라졌다. 교훈: 프레임 내용에 따라 변하는 값으로 모델의
불변 속성을 추정하면 안 되며, 지표와 실물이 다르면 코드 경로 차이부터 의심해야 한다.

버그 수정 후 P + 부위 수준 결정(7.4절) + 손 제어 조합으로 실물 파지에 성공해 이 구성을
기본 배포로 확정했다.

정답은 손잡이 47장, 몸통 50장에 있고 기능 영역은 없다. 신뢰도 0.25 고정, 클래스별 합집합

| 모델 | handle 평균 | handle 중앙값 | handle 완전 누락 | body 평균 | body 중앙값 | body 완전 누락 |
|---|---:|---:|---:|---:|---:|---:|

| M (RF-DETR, 자체 v3) | **0.7557** | **0.8681** | **5 / 47** | 0.9066 | 0.9533 | 0 / 50 |

읽는 방법은 세 가지다.

첫째, 몸통은 처음부터 문제가 아니었다. 어떤 모델도 완전 누락이 없고 IoU는 0.86 이상이다.

둘째, 손잡이는 학습에 쓴 세 머그와 생김새가 다른 네 번째 머그에서 확실히 어려워진다.
`mug_03` validation에서 handle mAP50이 0.85였던 H가 `mug_04`에서는 47장 중 16장의 손잡이를
아예 놓쳤다. 미학습 인스턴스 평가를 따로 잡아둔 이유가 여기 있다.

셋째, 손잡이 성능을 올린 요인은 두 가지였다. 자체 데이터에 가위·드라이버 같은 다른 손잡이
형상을 넣은 것(H→L, 0.4315→0.6247)과 모델 계열을 바꾼 것(H→K, 0.4315→0.6662)이 각각
효과를 냈고, 둘을 합친 M이 가장 좋았다(0.7557, 완전 누락 5장).

중앙값이 평균보다 훨씬 높다는 점도 눈여겨볼 만하다. M의 손잡이 중앙값은 0.868인데 평균은
0.756이다. 대부분의 프레임에서는 잘 맞고, 손잡이가 거의 보이지 않는 몇몇 각도에서 크게
실패해 평균을 끌어내린다는 뜻이다. 이런 프레임은 후보 선택 단계에서 `ALIGN`으로 처리해
사용자에게 손 위치를 바꾸도록 유도하는 것이 맞다.

### 5.5 선행 연구 대비 (가중 F-measure)

UMD 부품 affordance 분할 문헌은 가중 F-measure(F_β^w, Margolin et al. 2014)를 표준 지표로
쓴다. 최종 모델을 같은 지표·같은 UMD test 1,288장에서 측정해 문헌 보고값과 나란히 놓았다.
측정에는 2026-08-27에 만든 `scripts/evaluate_weighted_fmeasure_rfdetr.py`를 썼다.

| 방법 | Grasp 계열 | W-grasp / 몸통 | 기능부 계열 | 평균 |
|---|---:|---:|---:|---:|
| HMP (Myers et al. 2015) | 0.367 | 0.373 | 0.415 ~ 0.767 | 0.557 |
| DeepLab | 0.620 | 0.730 | 0.600 ~ 0.880 | 0.733 |
| ED-RGBD (Nguyen et al. 2017) | 0.714 | 0.767 | 0.723 ~ 0.806 | 0.770 |
| AffordanceNet (Do et al. 2018) | 0.731 | 0.814 | 0.762 ~ 0.836 | **0.799** |
| **P (최종 모델, 3클래스)** | 0.620 | **0.852** | 0.745 | 0.739 |

몸통은 AffordanceNet의 W-grasp보다 높고 손잡이는 낮다. 손잡이가 낮은 이유는 5.1절과 같다.
얇고 가림이 많은데 최종 모델은 312 입력의 실시간 경량 모델이다.

이 비교는 순위를 주장하기 위한 것이 아니다. 조건이 여러 가지로 다르다.

- 우리는 `contain`을 ignore로 제외했다. AffordanceNet은 contain을 포함해 예측하는데,
  contain은 원래 점수가 높은 클래스(0.833)라 평균에 유리하다.
- 클래스를 7종에서 3종으로 재편했고 test 분할도 우리 기준이다.
- F_β^w는 소프트 확률 맵을 전제하는 지표인데 RF-DETR은 고정 쿼리에 이진 마스크를 낸다.
  임계값 0.15에서 최고(0.739)이고 0.01로 낮추면 0.13까지 떨어진다. 지표가 출력 형식을
  일부 측정한다는 뜻이다. 표의 값은 임계값을 훑어 최고점을 쓴 것이다.

따라서 "같은 지표로 잰 참고값"으로만 제시한다. 이 프로젝트의 목표는 벤치마크 최고 성능이
아니라 실시간 파지로 잇는 것이고, 그 관점의 지표는 5.1절의 픽셀 IoU와 5.3절의 미학습
인스턴스 평가다.

### 5.7 실행 간 분산을 측정하지 못한 이유

같은 설정을 seed만 바꿔 여러 번 돌려 분산을 보려고 했는데, Ultralytics 8.3.163에서는 seed를
바꿔도 결과가 완전히 같았다. 데이터로더 순서에 seed가 반영되지 않아 파이프라인이 결정적으로
동작하기 때문이다. 그래서 train 이미지 목록의 순서를 바꾼 데이터셋(ord43, ord44)을 따로 만들어
다시 돌렸다. 그런데도 실험 I의 세 실행이 mask mAP50 0.8421로 완전히 일치했다. 목록 파일을
정렬해 해시를 비교하니 내용 자체는 같았고, 학습 파이프라인이 파일 순서까지 정규화하는 것으로
보인다.

실험 H에서는 ord 실행이 0.8089, 기준 실행이 0.8067로 조금 달랐는데, 이는 순서 때문이 아니라
ord 데이터셋을 만들 때 자체 데이터가 v1이 아닌 v2(절개선 적용)로 들어갔기 때문이다.

결론은 현재 방식으로는 실행 간 분산을 측정하지 못했다는 것이다. 보고하는 수치는 모두 단일
실행 결과이며, 표에서 0.005 안팎의 차이는 유의미하다고 말할 수 없다. 분산이 필요하면 초기
가중치 난수나 증강 난수를 실제로 흔드는 방법을 따로 설계해야 한다.

## 6. 인간 파지 행동으로 설계 근거 확보

"물체를 보고 왜 그렇게 잡는다고 말할 수 있느냐, EPIC-KITCHENS 같은 걸 참고해 보라"는 지도교수

EPIC-KITCHENS VISOR의 sparse 주석(158개 비디오, 40,604 프레임)에서 사람 주석자가 확정한
손-물체 접촉 이벤트 53,605건을 모으고, 관심 물체 20종을 대상으로 비디오 라운드로빈 층화 추출로
895장면을 골랐다. 물체를 노랑, 손을 빨강 윤곽으로 렌더링한 오버레이를 보며 868장면을 사람이
직접 5분류(손잡이 / 몸통 / 테두리·꼭지 집기 / 기능부 접촉 / 파지 아님)로 판정했다.

|---|---|---|
| 자루 도구(칼·국자·주걱·팬·주전자) | 손잡이 91~100% | handle 후보 우선 |

머그와 컵에서 손잡이와 몸통이 반반으로 갈린다는 결과가 이 프로젝트의 전제를 그대로 뒷받침한다.
사람도 상황에 따라 다르게 잡으므로, 하나의 정답을 고정하는 대신 후보를 여러 개 두고 접근

기록하고, 가중치 0.08의 보조 항으로 쓴다. 물체 이름이 아니라 모델 클래스로 조회하므로 물체

판정자 1인 한계는 AI 제2 판정자 전수 대조로 보완했고, 같은 작업에서 **자세를 직접 관찰**해
기록했다(2026-08-26). 868장 전수를 VLM이 사람 라벨을 보지 않은 상태로 재판정하면서 부위
5분류와 자세(집기/감아쥐기/움켜쥐기/접촉/비접촉)를 함께 남겼다.

부위 판정은 사람과 잘 맞았다. 5분류 전체 일치는 76.4%(κ=0.645)이고, 설계 통계에 실제로
쓰이는 **파지 3분류에서는 일치 89.9%(κ=0.820)**다. 불일치는 대부분 통계에서 제외되는

자세는 사람 판정에 없던 항목이므로 VLM 관찰이 유일한 출처다. 표의 행(부위)은 사람이 판정한

| 사람이 판정한 부위 | n | 그 부위에서 관찰된 자세 (VLM) |

특히 **같은 '손잡이'라도 구조가 자세를 가른다**는 점이 전수 관찰로 확인됐다. 팬·주전자의

**자세는 단일 판정자(VLM) 관찰이라는 점도 명시한다** — 부위처럼 사람과 대조할 라벨이 없다.
파지 선택은 작업에 따라 달라진다(마실 때와 옮길 때가 다르다). 그래서 prior는 1차 신호가

## 7. 파지 후보 선택과 자세 결정

### 7.1 후보 추출

마스크의 centroid는 쓰지 않는다. 고리형이나 굽은 형상에서는 centroid가 마스크 바깥이나
경계 근처에 찍힌다. 대신 distance transform의 최댓값 지점을 파지점으로 쓴다. 경계에서 가장
멀리 떨어진 안쪽 점이고, 그 최댓값(내접원 반지름)의 두 배를 후보 폭 추정치로 쓴다. 손가락이
실제로 닿는 국소 폭에 해당하는 보수적인 추정이다.

같은 클래스라도 분리된 연결 성분은 각각 독립 후보로 유지한다. 머그 손잡이와 몸통이 별도
후보가 되는 것이 이 규칙 덕분이다. `functional_region`은 후보가 아니라 회피 대상으로 따로
보관해 안전거리 계산에 쓴다.

### 7.2 점수식

```text
S = 0.22·C + 0.30·D + 0.22·A + 0.10·F + 0.08·M + 0.08·H
```

- `C` 검출 신뢰도
- `D` 손과 후보 사이 거리(최근접 후보 대비 비율)
- `A` 손 접근 방향과 후보 방향의 정렬
- `F` 후보 폭과 손 개구 범위의 적합도
- `M` 기능 영역으로부터의 안전 여유
- `H` 인간 파지 사전확률(6절)

모든 항은 0~1로 정규화하고 가중치 합이 1이 아니면 설정 로드 단계에서 오류를 낸다. 접근 방향
기반 선택이 목적이므로 상황 신호인 거리와 방향에 무게를 실었다. 이 값들은 초기값이며
validation 근거 없이 확정하지 않는다.

최고 점수가 0.45 미만이거나 1·2위 점수 차가 0.08 미만이면 파지하지 않고 `ALIGN` 상태로
사용자에게 재정렬을 요구한다. 파지점이 기능 영역과 12픽셀 이내면 후보 자체를 거부한다.

### 7.3 자세 결정

처음에는 세 자세를 후보 폭(마스크 내접원 지름)과 픽셀 임계값 40으로 나눴다. 실물 시험에서
이 방식은 두 가지로 무너졌다. 픽셀 폭이 카메라 거리에 좌우되어 같은 물체도 거리에 따라
자세가 뒤집혔고(가위·드라이버 자루가 WRAP으로, 작은 머그 손잡이가 PRECISION으로),
임계값 40 자체에 실측 근거가 없었다.

그래서 6장의 VISOR 판정 868건을 원본 주석에 다시 연결해 각 장면의 손·물체 마스크를
복원하고(868/868 성공), 모든 치수를 손바닥 폭으로 나눈 무차원 비율로 기하 특징을 측정했다.
비율은 카메라 거리와 무관하므로 통계에서 얻은 경계를 실행 시에 그대로 쓸 수 있다.
세 가지가 나왔다.

첫째, **잡은 부위의 폭은 파지 유형을 가르지 못한다.** 손잡이 파지든 몸통 파지든 테두리
집기든 사람이 잡은 부위의 두께는 손바닥 폭의 15~19%로 거의 일정했다(1차원 경계의
균형정확도 0.50). 폭 임계값 방식이 실패한 근본 이유다. 둘째, 자세를 가르는 것은 물체의
구조다. 손잡이 파지 418건을 도구 자루(칼·가위·숟가락류)와 용기의 부속 손잡이(머그·주전자류)로
나누면 물체 전체 종횡비 경계 2.12에서 균형정확도 0.936, 부속성(잡은 부위 두께/물체 최대
두께) 경계 0.27에서 0.805로 갈린다. 셋째, 테두리 집기는 작은 물체가 아니라 크고 둥근
물체(접시·뚜껑)에서 나온다. "작으면 집기"라는 직관은 2D 투영에서 성립하지 않는다.

현행 규칙은 이 측정에서 나왔다. body 후보는 POWER, 손잡이 후보가 body 영역과 인접하면
용기의 부속 손잡이로 보고 WRAP, 그 외에는 물체 문맥(손잡이와 인접 기능영역의 합집합)의
종횡비가 2.1 이상이면 도구 자루로 보고 PRECISION, 미만이면 WRAP이다. 모든 특징이 비율과
인접성이라 거리·mm 보정과 무관하다. 종횡비 판별기는 5-겹 교차검증 20회에서 0.927±0.025,
부트스트랩 95% 신뢰구간 [0.929, 0.936]이었고, 물체별 hold-out(해당 물체를 빼고 학습해
그 물체를 분류)에서도 0.82~1.00을 유지했다. 실물 시험에서도 판정이 의도대로 동작했으며,
유일한 실패였던 투명 2L 물병은 당시 상류 분할의 도메인 밖 오류로 해석했으나, 이후
실시간 클래스 기준 버그(4.10절)가 발견되면서 그 증상(body 단독 검출 프레임이 handle로
밀려 PRECISION 판정)과 정확히 일치함이 확인됐다 — 버그 수정 후 재현되지 않는다.

근거의 성격은 구분해 둔다. "폭은 기준이 될 수 없다"와 "종횡비·부속성이 두 물체군을
가른다"는 사람 데이터가 직접 뒷받침하고, "도구 자루를 PRECISION으로 잡는다"는 배정은
사람 행동(도구 자루는 주로 감아쥠)이 아니라 Brunel Hand의 능력 제약(3지 집기가 가는
막대에 적합)에 따른 설계 결정이다. 상세 분석·그림·선행 연구 대응은
`docs/grasp_pose_geometry_analysis.md`에 있다.

### 7.4 부위 수준 결정으로의 전환 — 파지점 폐지 (2026-08-26)

초기 설계는 후보마다 파지점(distance transform 내부점을 손 위치에 맞춰 재선정)을 계산해
표시와 판정에 썼다. 그러나 실물에서 손이 목표에 근접하면 마스크가 잘리며 파지점이
사라지거나 요동하는 문제가 반복됐고, 이를 막는 안정화 장치(가림 중 유지, 트랙 매칭 완화,
유령 후보)를 겹겹이 쌓게 됐다. 이 시점에 파지점의 역할을 재검토했다: **구동은 접촉(스톨)
적응이 담당하므로 파지점은 모터 목표로 쓰이지 않고**, 판정에서의 역할(방향 정렬·기능부
회피·타이브레이크)은 모두 부위 마스크 수준으로 대체 가능하며, 표시(사용자 유도)는 부위
강조가 오히려 명확하다. 그래서 파지점을 판정에서 빼고 **손 접근 × 물체 부위**만으로
자세를 결정하는 부위 수준 결정으로 전환했다.

이 구조는 반자율 의수의 공유 제어(shared control)와 정합한다. Došen et al.(2010),
Marković et al.(2014)의 반자율 의수에서도 비전이 결정하는 것은 파지 유형과 개구이지
접촉점이 아니며, 조준과 파지 시점은 사용자의 몫이다(우리의 스페이스 트리거는 근전도
신호의 대역이다). 국소 접촉 위치의 오차는 스톨 기반 적응 파지가 흡수한다.

기능부 회피는 "파지점이 기능부와 12px 이내면 거부"에서 "**부위 픽셀의 50% 초과가 그
거리 안이면 거부**(얽힘 비율)"로 바꿨다. 드라이버 자루처럼 날과 맞닿았지만 대부분이
안전한 부위는 통과하고, 날을 따라 붙은 조각만 거부된다.

가림 강건성은 **유령 후보**가 담당한다. 검증을 통과한 후보의 스냅샷을 저장해 두고,
근접 가림으로 후보가 소멸하면(모델 미검출·손 픽셀 제거·손 박스 거부) 스냅샷을 대신
내보낸다. 정지 장면 가정에서 물체는 손 뒤 그 자리에 있기 때문이다. 손이 그 자리를 덮는
동안은 유지 시한을 세지 않고(호버 무기한), 다른 안정 후보가 그 자리를 덮으면 교체
증거로 보고 즉시 폐기하며, 실측 후보가 나타나면 점수 할인으로 즉시 양보한다. 실제 접근
영상 792프레임 재생 계측에서 접근·가림 중 선택 소실이 0프레임이었고, 결정 연산도 점
기반보다 빨랐다(12.8ms 대 20.3ms). 실물에서 부위 강조의 안정성을 확인하고 이 경로를
기본으로 확정했다(점 기반 경로는 A/B 비교를 위해 보존).

## 8. 로봇손 추적: ArUco에서 손 검출로

계획 단계에서는 손목에 ArUco 마커를 붙여 위치와 접근 방향을 얻으려고 했다. 실제로 해 보니
마커를 붙이고 유지하는 것 자체가 번거롭고, 손이 물체에 가까워질수록 마커가 가려졌다. 그래서
손 자체를 검출하는 방향으로 바꿨다.

현재 기본 백엔드는 배경 차분과 프레임 간 차분을 결합한 `motion`이다. 검은 의수를 검은 책상
위에서 찍은 영상으로 파라미터를 맞췄다. 접근 방향은 마커 자세 대신 손 위치 변화의 지수이동평균
(속도 벡터)으로 추정하고, 속도가 작으면 방향 없음으로 두어 정지 상태에서 엉뚱한 방향이 나오지
않게 했다. 검출이 15프레임 이상 끊기면 손 상태를 무효로 만든다. 오래된 위치로 파지를 결정하지
않기 위해서다.

MediaPipe Hands도 시험했다. 지연은 18.8 ms로 충분히 빨랐지만 검출률이 42%였고 손목 좌표
지터가 평균 24.5픽셀, 상위 10%에서 61.6픽셀이었다. 사람 손 기준으로 학습된 모델이라 로봇손에
그대로 쓰기는 어렵다고 판단했다. YOLO-World 제로샷("robot hand" 프롬프트)은 라벨링 보조용으로
남겨 두고, 촬영 데이터로 전용 검출기를 학습하는 것을 2단계로 계획했다.

실측 손 폭을 넣으면 화면 폭과의 비로 `mm_per_px`를 추정할 수 있게 설계했다. ArUco 캘리브레이션을
대신하는 경로다. 2026-08-25 실측(펼친 손 가로 120mm)을 설정에 반영했고, 추정에는 검출 박스의
짧은 변을 가로 폭에 대응시켜 회전에 덜 민감하게 했다.

젯슨 실전에서는 motion 백엔드가 추가로 한계를 드러냈다. 파라미터가 튜닝 영상의 환경에 묶여
있어 조명과 배경이 바뀐 실제 장면에서 손을 잡지 못했고, 원리상 정지한 손도 못 본다. 두 가지로
대응했다. 먼저 분할 모델이 로봇손을 파지 후보로 오인하는 문제에는 후보 억제 필터를 넣었다
(`src/grasp_selection/hand_filter.py`). 실물 시험에서 증상이 하나씩 드러날 때마다 방어를
더해 최종적으로 다섯 겹이 됐다.

첫째는 시간 안정성이다. 고정 카메라에서 움직이는 것은 손뿐이므로 몇 프레임 연속 같은 자리에
있는 후보만 물체로 인정한다. 화면을 지나가는 손이 만드는 오검출은 위치가 계속 바뀌어 자동으로
걸러진다. 둘째는 손 박스와의 겹침 거부다. 손 영역 안에 후보 면적의 큰 비율이 들어가면 거부하되,
접근 중 목표물이 손과 살짝 겹치는 경우를 지키려고 면적 비율 기준을 쓰고 추적이 유효한 프레임에만
적용한다. 오래된 박스로 거부하면 진짜 목표를 죽인다.

셋째는 클래스 다수결이다. 트랙 매칭은 클래스와 무관하게 위치·면적으로 하고 최근 관측 창의
다수결로 클래스를 확정한다. 종이컵처럼 결정 경계에 걸린 물체가 handle과 body를 오가면 클래스별
트랙이 매번 리셋되어 후보가 영영 불안정으로 거부되던 문제를 이렇게 풀었다. 넷째는 파지점
안정화다. 손이 물체를 가려 마스크가 잘리면 잘린 마스크로 계산한 파지점이 가림 경계로 끌려간다.
물체는 움직이지 않았으므로 가림 동안에는 마지막 안정 점을 유지하고, 마스크가 온전할 때만
지수이동평균으로 떨림을 없앤다.

다섯째가 후보 홀드다. 손이 물체를 거의 덮으면 후보 자체가 소멸해 파지 직전에 대상을 잃는다.
넷째 장치는 후보가 살아 있어야 작동하므로 최종 접근 구간은 이쪽이 맡는다. 자세한 동작과
안전장치는 7.4절에 있다.

겹침 문제는 셋째부터 다섯째가 함께 담당한다. 손이 다가올수록 마스크가 잘리고 클래스가 흔들리다
끝내 후보가 사라지는데, 단계마다 다른 장치가 받는 구조다. 실제 접근 영상 792프레임 재생
계측에서 접근·가림 중 선택 소실이 0프레임이었다.

근본 해결로는 분할 모델에 robot_hand 클래스를 추가하는
실험을 진행했다(4.9절). 이 경로가 완성되면 별도 추적기 없이 한 번의 추론으로 물체와 손이 함께
나오고, 정지한 손도 추적되며, 실시간 스크립트의 `--hand-source segmentation`이 그 마스크에서
손 위치와 접근 방향을 만든다.

## 9. 하드웨어 제어

### 9.1 구성

Brunel Hand V2.0에 PQ12-100-12-P 리니어 액추에이터 네 개(검지, 중지, 약지·소지, 엄지)를
DRV8833 두 개로 구동하고, Arduino Nano 33 IoT가 저수준 제어를 맡는다. 모터 전원은 10 V,
보드는 USB 전원이며 GND는 공통이다. 위치 피드백은 각 액추에이터의 포텐셔미터를 A0~A3으로
읽는다(12비트).

### 9.2 피드백 정상화

처음에는 A0 값이 2~16 사이에서 위치와 무관하게 움직여 피드백을 쓸 수 없었다. 3V3 공급선과
wiper 배선을 짚어가며 다시 연결하자 검지가 살아났고, 8월 21일 밤 나머지 세 채널도 배선 수정
후 한꺼번에 정상화됐다. 세 채널이 동시에 같은 증상이었던 것으로 보아 3V3 분배가 원인이었던
것으로 보인다.

### 9.3 실측 보정값

100 ms 펄스를 한 번씩 보내며 값이 멈출 때까지 기록하는 방식으로 네 손가락의 전 행정을 측정했다.

| 손가락 | 낮은 한계 | 높은 한계 | 전 행정 시간(↓ / ↑) | 펼침 방향 |
|---|---:|---:|---|---|
| 검지 (A0) | 333 | 3457 | 1.0 s / 1.5 s | 방향 1 (높은 ADC) |
| 중지 (A1) | 432 | 3500 | 1.0 s / 1.4 s | 방향 2 (높은 ADC) |
| 약지·소지 (A2) | 422 | 3550 | 0.9 s / 1.3 s | 방향 1 (높은 ADC) |
| 엄지 (A3) | 309 | 3552 | 1.6 s / 2.2 s | 방향 2 (낮은 ADC) |

네 손가락 모두 ADC가 낮아지는 방향이 빠르다. 중지는 명령 번호와 ADC 증감의 대응이 검지와
반대인데, 배선을 바꾸지 않고 펌웨어 설정으로 흡수했다. 끝 위치에서 같은 방향을 한 번 더 주면
값이 40 정도 되돌아오는 현상이 있어 소프트 한계는 기계 한계에서 80 이상 안쪽에 두었다.
정지 상태 잡음은 8회 평균 기준 28~58 count였고, 이를 근거로 deadband 50, 스톨 판정 기준
200 ms에 60 count 미만으로 잡았다. 이 값들은 `configs/hardware/hand_actuators.yaml`에
근거 로그 경로와 함께 기록했다.

엄지만 펼친 상태가 낮은 ADC다. 센서 극성이 반대인 것으로, 사용자 육안 확인으로 8월 21일
21시 55분에 확정했다.

### 9.4 폐루프 펌웨어

사용자가 쓰던 100 ms 펄스 스케치는 `delay()` 기반이라 펄스 도중 정지 명령을 받지 못하고
최대 구동시간이나 스톨 감지가 없었다. 그래서 `millis()` 기반 비차단 상태 머신으로 새 스케치를
작성했다. 기존 스케치는 진단용으로 그대로 두었다.

프로토콜은 115200 baud 줄 단위 ASCII다. `MOVE`, `MOVEALL`, `FRAC`(닫힘 비율), `OPEN`,
`STOP`, `POS`, `STATUS`, `SET CAL`, `PING`을 지원하고 `EVT DONE/STALL/TIMEOUT/HEARTBEAT_STOP`을
비동기로 올린다. `STOP` 파싱은 다른 명령보다 먼저 처리한다. 보정값이 없으면 `UNCAL` 상태로
구동을 거부한다.

책임 분리는 이렇게 두었다. 펌웨어는 저수준 안전(최대 구동시간, 스톨, heartbeat 끊김, 정지)과
손가락별 위치 폐루프만 담당하고 프리셋과 정책은 모른다. 호스트가 YAML 하나를 진실로 삼아
보정값과 프리셋을 관리하고, 프리셋은 손가락별 닫힘 비율 0~1로 정의해 보정이 바뀌어도 그대로
쓸 수 있게 했다.

벤치와 실동작 시험까지 마쳤고, 값이 필요한 곳은 전부 실측으로 채웠다.

- **도달 정확도**: deadband를 50/25/12로 바꿔 왕복시킨 결과 평균 오차 45.5/20.5/7.0에
  모두 진동이 없었다. 기본값을 20으로 정했고 전체 접기/펼치기 오차는 ±17 수준이다.
- **위치 유지**: 목표 도달 후 coast로 두면 3초에 279 카운트 처졌고 brake는 40이었다.
  파지 유지에 필수라 brake를 기본으로 바꿨다.
- **적응형 파지**: 물체 크기별 목표를 정하지 않는다. 최대로 닫되 0.2초간 진행이 없으면
  스톨로 판단해 정지하는 방식이라, 물체에 닿는 지점이 곧 파지 지점이 된다. 손으로 막은
  시험에서 막힌 지점 정지, brake 유지(3초 +22), OPEN 복귀까지 확인했다.
- **구동 순서**: 같은 머그로 연속 비교한 결과 네 손가락을 동시에 닫으면 물체가 밀려나
  전부 100%까지 헛닫혔고, 엄지를 먼저 세운 뒤 나머지를 닫으면 세 손가락이 78~82%에서
  스톨하며 실제로 쥐었다. 프리셋에 구동 순서(`preset_sequence`)를 도입해 POWER/WRAP은
  엄지 먼저, PRECISION은 약지·엄지 먼저로 정했다.
- **프리셋**: 참여 손가락은 최대로 닫는 방식으로 사용자가 확정했다 — PRECISION [1,1,0,1],
  WRAP [1,1,1,0], POWER [1,1,1,1]. 스톨 정지가 물체 크기에 맞춰 주므로 비율을 물체별로
  조정할 필요가 없다. 주의할 점으로, 스톨 여부만으로 파지 성공을 판정하면 안 된다.
  WRAP은 손가락이 구조상 최대 굽힘에서 DONE으로 끝나고 얇은 물체는 끝까지 닫히며 쥐므로,
  성공 판정은 들어올림 기준(13.3절 프로토콜)으로만 한다.

파이썬 클라이언트(`src/hand_control/`: protocol/presets/link/client/state_machine)와 젯슨
이관도 완료했다. 젯슨에는 pyserial이 이미 있었고, ModemManager가 tty에 AT 명령을 보내는
문제는 udev 규칙(VID 2341/PID 8057 무시 + 고정 이름)으로 회피한다. 시리얼 응답이 밀리는
포트 동시 사용 사고를 겪은 뒤 클라이언트가 명령별 기대 응답을 검증하도록 보강했다.
MockLink 기반 단위·통합 시험이 손 제어 계열에서 57개 통과한다.

## 11. 현재 한계와 주장할 수 있는 범위

**말할 수 있는 것**

- 공개 affordance 데이터 세 종을 하나의 라벨 체계로 통합하고, 물체 ID 기준 분할과 정책 감사를
  갖춘 재현 가능한 파이프라인을 만들었다.
- 실제 사용할 카메라로 찍은 자체 데이터 292장을 전량 사람 검수로 구축했다.
- 학습에 쓰지 않은 실물 머그 한 개에 대해 손잡이·몸통 분리 검출을 정량 평가했고, 자체 데이터
  확장과 모델 계열 교체가 각각 손잡이 성능을 개선했다.
- 미세조정 중 망각을 진단하고 replay 혼합으로 회복했다.
- 후보 선택과 자세 결정 규칙을 인간 파지 행동 통계로 뒷받침했다.

**말하면 안 되는 것**

- 모든 물체에 대한 일반화. 미학습 인스턴스 평가는 머그 한 종류뿐이고, 가위와 드라이버는 실물이
  하나씩이라 학습에만 썼다.
- 자체 데이터로 기능 영역 성능을 검증했다는 주장. `mug_04` test에는 기능 영역 정답이 없다.
  기능 영역은 공개 데이터 평가로만 확인했다.
- 수치 차이의 유의성. 실행 간 분산을 측정하지 못했으므로 0.005 안팎의 차이는 근거로 쓰지 않는다.
- YOLO와 RF-DETR의 공정한 모델 비교. 초기 가중치와 입력 해상도가 함께 다른 파이프라인 비교다.
- 실시간 성능의 최종 수치. Jetson 실측이 없고, 로컬 카메라 루프 값은 세션 편차가 크다.

**아직 하지 않은 것**

- 실제 파지 성공률 실험(테이블에서 5 cm 이상 들어 올려 3초 유지). Baseline 1(고정 POWER),
  Baseline 2(최근접 후보), 제안 방식의 비교가 통째로 남아 있다.
- 폐루프 펌웨어 벤치 시험과 세 프리셋 확정.
- `src/hand_control/` Python 클라이언트와 상태 머신.
- 손 최대 개구 폭 실측과 mm 스케일 확정.
- 실험 L의 공개 test·자체 validation mAP 평가(현재 L은 혼합 validation과 `mug_04` 픽셀 IoU만 있다).
- Jetson 런타임 구축. 8월 24일에 Orin Nano Super 접속과 작업 디렉터리 준비까지만 했고 런타임은
  아직 설치하지 않았다.

## 12. 남은 일정 (발표일 2026-08-28 기준)

기본 모델 교체 판단(P 채택), 실시간 base 버그 수정, 부위 수준 결정 전환, 손 제어 통합과
실물 파지 검증, 성공률 시험 기록 도구까지 끝났다. 발표 전 남은 것은 다음과 같다.

1. **파지 성공률 실험** — Baseline 1(비전 없음, 고정 POWER)과 제안 방식을 물체 5종 ×
   각 10회로 비교한다(성공 기준: 들어 올려 3초 유지). 기록 도구
   `scripts/run_baseline_grasp_trials.py`가 두 조건을 같은 CSV에 남긴다. 접촉 적응은 두
   조건이 동일하므로 차이는 비전이 고른 부위·자세의 기여분이다. 결과는 5장에 표로 추가한다.
2. **손 최대 개구 폭 실측** — 폭 필터의 110mm는 아직 추정값이다. 실측값으로 교체한다.
3. **발표자료(PPT)** — 이 보고서 기반. 실험 N 실패와 base 버그는 지표-배포 괴리 사례로
   포함한다. 라이브 시연이 가능하면 P + 부위 결정 + 손 제어 기본 구성으로 리허설한다.

발표 이후로 미루는 것: mug_04 재평가(파란 머그와의 외형 유사성 명시 필요). 한때 목록에
있던 PRE_SHAPE 값·투명 용기·원통 보강 촬영은 제외한다 — 앞의 둘 문제는 실시간 클래스
기준 버그(4.10절)의 증상을 별개 문제로 오인한 것이었고 수정 후 재현되지 않으며(투명
물병의 PRECISION 오판은 body 단독 검출 프레임이 handle로 밀리는 버그 서명과 정확히
일치한다), PRE_SHAPE는 통합 검증(5.7절)에서 파지가 완전 펼침 상태로도 문제없이 성립해

## 부록 C. 용어

| 용어 | 뜻 |
|---|---|
| `handle_grasp_region` | 손잡이처럼 감아쥐거나 집는 파지 영역 (모델 클래스 0) |
| `body_grasp_region` | 몸통처럼 움켜쥐는 파지 영역 (모델 클래스 1) |
| `functional_region` | 날·팁·가열부처럼 이번 작업에서 피해야 하는 영역 (모델 클래스 2) |
| `ignore` | 의미가 모호하거나 정책과 충돌해 학습에서 제외하는 픽셀 (255) |
| 절개선(ring slit) | 구멍 있는 마스크를 폭 0의 선으로 이어 단일 폴리곤으로 만드는 변환 |
| replay 혼합 | 미세조정 데이터에 공개 데이터를 섞어 망각을 막는 방식 |
| 픽셀 IoU | 신뢰도 임계값을 고정하고 클래스별 합집합 마스크로 계산한 IoU (AP와 구분) |

파지 자세 명칭과 표준 분류(Napier 1956; Cutkosky 1989; Feix et al. 2016)의 대응:

| 본 시스템 명칭 | 동작 | 표준 분류 대응 |
|---|---|---|
| POWER | 엄지 먼저, 전 손가락으로 몸통 감싸쥠 | power grasp (일치) |
| WRAP | 엄지 제외 손가락을 구부려 손잡이에 걺 | **hook grasp** (Cutkosky #15; 문헌의 "wrap"은 power 하위 유형이라 내부 명칭과 다름 — 코드 호환을 위해 명칭 유지) |
| PRECISION | 엄지+검지+중지 3지 집기 | precision grasp의 tripod 유형 (일치) |
